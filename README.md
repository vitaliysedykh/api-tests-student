## Запуск тестов

1. Установите любое IDE для разработки: [Jetbrains GoLand](https://www.jetbrains.com/ru-ru/go/) (Платное или по студенческой лицензии), [VS Code](https://code.visualstudio.com/) (бесплатное).
2. Установите [Git](https://git-scm.com/install/) на компьютер
3. [Установите](https://go.dev/doc/install) Go версии 1.25.1 или выше
4. [Настройте](https://docs.github.com/ru/authentication/connecting-to-github-with-ssh) доступ к своему Github-аккаунту
   по SSH-ключу.
5. Склонируйте себе репозиторий: `git clone <путь к вашему репозиторию>`
6. Подтяните необходимые зависимости через команду в корне проекта:

```bash
   go mod tidy
```

7. В файле `.env.override` (создайте его в корне, если нет) выставьте правильные значения для переменных окружения:

```
TEST_LOGIN=your_login
TEST_PASSWORD=your_password
```

8. Для запуска всех тестов достаточно выполнить команду в корне проекта:

```bash
  go test -v ./...
```

9. Отдельный пакет с тестами можно запустить командой:

```bash
  go test -v ./tests/scenarios/myAdvertisement/
  go test -v ./tests/scenarios/createAdvertisement/
  go test -v ./tests/scenarios/favorites/
```

Сценарий `myAdvertisement` из шаблона ожидает, что у пользователя из `TEST_LOGIN` уже есть объявления с фотографиями.

## Покрытые сценарии

| Пакет | Файл | Что проверяется |
|---|---|---|
| `createAdvertisement` | `createAdvertisementPositive_test.go` | Объявление со всеми параметрами и 3 фотографиями: `GET /advertisement?id=` возвращает переданные параметры, `GET /advertisements?search=` находит его по полному названию, `GET /advertisements/{id}/photos` отдаёт загруженные фото, файлы скачиваются из хранилища и являются PNG |
| `createAdvertisement` | `createAdvertisementNegative_test.go` | 400: пустые название и описание, нет фото, название > 50 символов, описание > 500, цена < 0 и > 1 000 000, количество < 1 и > 100, фото > 3. 401: без токена и с неверным токеном |
| `favorites` | `favoritesPositive_test.go` | Добавленное объявление появляется в `GET /favorites`, удалённое из избранного — пропадает; объявление, удалённое владельцем через `DELETE /advertisement`, пропадает из избранного |
| `favorites` | `favoritesNegative_test.go` | 404: добавление и удаление несуществующего объявления. 401: все ручки избранного без токена и с неверным токеном. Ограничения `POST /favorites`: 409 — повторное добавление, 403 — своё объявление, 400 — id не в формате UUID, 400 — превышен лимит в 50 объявлений |

Из ошибок `POST /favorites`, описанных в swagger, не воспроизводится только 500.

### Тестовые данные

- Тесты регистрируют на TestBoard временных пользователей `autotest_…@example.com`: автора объявлений для каждого сьюта
  и отдельного покупателя для проверки лимита избранного. Объявления под пользователем из `TEST_LOGIN` не создаются,
  чтобы не менять данные, которые проверяет сценарий `myAdvertisement`; этот пользователь выступает покупателем в избранном.
- Каждый тест создаёт свои объявления с уникальным названием и удаляет их после себя, поэтому тесты независимы
  и дают одинаковый результат при повторных запусках.
- Фотографии генерируются во временной папке теста, в репозитории файлов с изображениями нет.

### Особенности API, учтённые в тестах

- Объявление запрашивается и удаляется по `id` в query-параметре: `GET /advertisement?id=`, `DELETE /advertisement?id=`.
- `GET /advertisements/{id}/photos` требует авторизацию.
- Нулевой UUID (`00000000-…`) API считает пустым полем и отвечает 400, поэтому для несуществующего объявления используется
  случайный валидный UUID.
- Каталог общий: объявления других пользователей могут удалить в любой момент. Для проверки лимита избранное заполняется
  самыми старыми объявлениями каталога, а уже удалённые пропускаются.
- TestBoard ограничивает частоту запросов (около 10 в секунду с одного адреса) и отвечает 503. Общий раннер
  повторяет такие запросы с нарастающей паузой (до 5 раз), повторы видны в логе с меткой `[RateLimit]`.

## Логирование

Для включения логирования request/response в консоль: выставьте переменную окружения `DEBUG=true` в
`.env.override`

Шаги тестов пишутся в консоль с метками `[Precondition]` (подготовка), `[Step]` (шаг), `[Result]` (результат проверки)
и `[Cleanup]` (удаление созданных данных). Вывод виден при запуске с флагом `-v`.
